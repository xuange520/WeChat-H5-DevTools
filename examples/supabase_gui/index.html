常见问题与排障全书 (FAQ & Troubleshooting)

内核注入、多进程锁定、透明代理、强缓存粉碎与大内存解混淆疑难速查

核心疑难高频速查索引
针对微信 4.x/RadiumWMPF 最新架构的工程级排障策略
Q1: 运行 wx-h5 提示“无法识别为 cmdlet 或命令”？
在项目根目录运行 pip install -r requirements.txt 与 pip install -e .，或直接使用 python main.py <命令> 启动。
Q2: 执行 wx-h5 hook 提示“已有微信进程在运行”？
微信处于登录常驻状态时无法由调试器冷启动。请完全退出托盘微信图标，或在终端执行 taskkill /F /IM WeChat.exe /IM Weixin.exe /IM WeChatAppEx.exe /T 后重试。
Q4: 启动透明代理后，微信内置浏览器无法联网或提示“代理拒绝连接”？
默认 8899 端口可能被 Clash、v2rayN、Fiddler 抢占，使用 wx-h5 proxy --port 8999 换端口；若出现 HTTPS 红色告警，将 ~/.mitmproxy/mitmproxy-ca-cert.cer 根证书双击安装至“受信任的根证书颁发机构”。
Q5: 微信大版本升级及 RadiumWMPF 内核更新后，工具如何做到免适配脱钩？
工具采用运行时 Chromium 虚表动态掩码特征扫描，放弃易失效的静态硬编码内存地址，并配合进程创建拦截、协议管道热注入与代理层三级容灾多路挂载。
Q6: 使用 Local Overrides 重定向后，刷新页面仍加载线上旧代码？
微信对 H5 启用了 Chromium 磁盘强缓存与 304 协商。工具代理层已默认粉碎缓存标头；亦可在 vConsole 的 Storage 中点击“Clear Cookies & Cache”，或在 URL 尾部添加随机时间戳 ?_t=... 击穿缓存。
Q8: 解混淆大型单体包（>5MB）时，Node.js 报错内存溢出 (OOM) 崩溃？
执行前配置 8GB 虚拟堆内存：$env:NODE_OPTIONS="--max-old-space-size=8192"；并配合 --chunked 增量分块反混淆参数，将内存峰值从 4GB 压缩至 400MB。
Q10: 执行 Hook 注入时提示“拒绝访问 (Access is denied / os error 5)”？
Windows UAC 完整性级别隔离导致。若微信是以管理员权限拉起的，终端也需右键“以管理员身份运行”；本项目发布的独立 EXE 已内嵌原生管理员权限清单，双击自动提权。
